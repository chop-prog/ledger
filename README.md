# Ledger

REST API переводов между счетами: счёт не уйдёт в минус, а повтор запроса не спишет деньги второй раз. Деньги здесь учебные.

_English: an ASP.NET Core API for account transfers. Atomic updates prevent overdrafts, idempotency keys make retries safe, and every account's entries add up to its balance._

C# · .NET 10 · ASP.NET Core Minimal API · EF Core · SQLite · xUnit

## Что здесь интересного

**Нельзя уйти в минус.** Проверка баланса и списание — один SQL-запрос (`where Balance >= amount`). Дополнительно в базе стоит ограничение `Balance >= 0`.

**Повтор запроса безопасен.** Клиент присылает заголовок `Idempotency-Key`. Если ответ потерялся и клиент повторил запрос, вернётся первый результат, а деньги не спишутся снова. Тот же ключ с другой суммой получит `422`.

**Двойная запись.** Каждый перевод оставляет две проводки, поэтому сумма проводок счёта всегда равна его балансу. Суммы хранятся в копейках целыми числами.

## API

| Запрос | Что делает |
|---|---|
| `POST /api/accounts` | Открыть счёт |
| `GET /api/accounts/{id}` | Счёт и баланс |
| `GET /api/accounts/{id}/statement` | Проводки по счёту |
| `POST /api/accounts/{id}/deposits` | Пополнить, нужен `Idempotency-Key` |
| `POST /api/transfers` | Перевести, нужен `Idempotency-Key` |

Ошибки возвращаются в формате RFC 7807 (`application/problem+json`).

## Запуск

Нужен .NET 10 SDK.

```bash
dotnet test
dotnet run --project src/Ledger
```

## Тесты

Каждый тест идёт через настоящий HTTP-конвейер и отдельный файл базы. Среди них: 200 параллельных переводов со счёта, на котором хватает только на 50; 30 параллельных повторов одного запроса; сохранение общей суммы при переводах между счетами.

## Ограничения

Учебный проект: нет авторизации, а SQLite выполняет записи по очереди. На PostgreSQL нужно отдельно продумать порядок блокировок и обработку гонки за ключ.
